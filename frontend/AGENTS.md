# frontend/AGENTS.md

Shared rules (git workflow, commenting) are in the root [`AGENTS.md`](../AGENTS.md).

## Layout

Single SvelteKit app; all commands run from `frontend/`.

| Path                                                          | Role                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `src/routes/`                                                 | Pages. `(entry)/` holds login and signup. `user/` holds the authenticated area: `projects`, `search-tags`, `logout`, and `[project_name]-[project_id=integer]/{todos,settings}`. `api/[...path]/+server.ts` proxies browser API calls to the backend (see `client-wrapper`). Route-local components (`CreateProject.svelte`, `EditTag.svelte`, ...) and Zod schemas (`validator.ts`) sit next to the `+page` files.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `src/params/`                                                 | Route param matchers (`integer`, `name`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `src/hooks.server.ts`                                         | Reads cookies into `event.locals` (`sharedCookies`, `token`). Drops expired tokens. The token cookie is `httpOnly` and never sent to the browser: page data only carries `username`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `src/lib/generated-client/`                                   | **Generated and committed. Never edit by hand.** Marked `linguist-generated` (collapsed in GitHub diffs) and ignored by ESLint/Prettier. Produced by [`@hey-api/openapi-ts`](https://heyapi.dev) (config: `openapi-ts.config.ts`) from the backend's OpenAPI 3.1 spec: `sdk.gen.ts` (one function per operation, e.g. `searchTags`), `types.gen.ts` (types, plus enums as objects such as `Permission.ALL`), `zod.gen.ts` (zod 4 schemas named like the backend models, e.g. `ProjectCreate`; per-operation inputs such as `zSearchTagsQuery`) and the fetch client runtime (`client/`, `core/`). Import from `$lib/generated-client` and `$lib/generated-client/zod.gen`. There is no module-level client: hey-api always emits one (`client.gen.ts`), and the config deletes it after each run because on the server it would be shared by every user's requests.                                          |
| `src/lib/client-wrapper/`                                     | `clients.ts`: `createApiClient(fetch)` builds a client for one request. Every SDK call takes one (`client` is required) and resolves to the response body; every failure rejects with `ApiError` (`body`, plus `response` when the server answered with an HTTP error). All calls, from the browser and from the server, go to the `/api` proxy route: it adds the token from the `httpOnly` cookie, checks `Origin` on writes, applies the timeout and forwards only `content-type`/`accept`. Server code passes the event's `fetch` (it handles `/api` in-process and forwards the cookies); browser code passes the global `fetch`. Only the proxy and `hooks.server.ts` touch the token. `wrapper.universal.ts`: `callService` maps every failure to a typed `ServiceError` (`ErrorType`). `wrapper.server.ts`: `callServiceInFormActions` for form actions. `wrapper.client.ts`: `callServiceInClient`. |
| `src/lib/actions/`                                            | Svelte actions: `form` (enhanced submit + Zod validator, `superFail`, `namedActionResult`, `validateFormActionRequest`), `drag-and-drop`, `class-manipulator`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `src/lib/stores/`                                             | State as classes in `*.svelte.ts` files using runes, each with a `context.ts` (`getX`/`setX`). `context-manager/` adds a root context so stores can be set "to root".                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `src/lib/components/`                                         | Shared components, grouped by folder (`forms`, `popups`, `buttons`, `project`, `todos`, ...).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `src/lib/utils/`, `src/lib/animations/`, `src/lib/constants/` | Helpers (token, zod key extraction, storage types, type utilities), transitions, cookie keys.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `tests/`                                                      | Playwright E2E. `tests/routes/**` mirrors `src/routes/**`. `tests/fixtures/` holds page-object classes exposed as Playwright fixtures. `tests/common-locators/` holds shared locators.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `openapi-ts.config.ts`                                        | hey-api config. Loads `.env` (without overriding existing env vars) and reads `$PUBLIC_API_URL/openapi.json`. The SDK functions require a `client`, return the response body (`responseStyle: 'data'`) and are typed for `throwOnError: true`, which `createApiClient` sets at runtime. `output.postProcess` deletes the generated module-level client (`client.gen.ts`). `@hey-api/openapi-ts` is pinned to an exact version because it is still 0.x.                                                                                                                                                                                                                                                                                                                                                                                                                                                       |

Data flow: page or component → `<form>` posts to a `+page.server.ts` named action → `validateFormActionRequest(request, schema)` → `callServiceInFormActions({ call: async () => await someOperation({ client: createApiClient(fetch), path, body }), errorSchema })` → `namedActionResult(result, 'name')` → `EnhancedForm` callbacks (`onSubmitSucceeded`) update the store.

## Tooling

From `package.json`, the configs, and `.github/workflows/test.yml`:

- Package manager: **pnpm 12** (`packageManager: pnpm@12.11.2`, `pnpm-lock.yaml`, CI via `pnpm/action-setup` reading `packageManager`, Vercel, `.vscode/launch.json`). Dependency build scripts only run when allowed in `pnpm-workspace.yaml` (`allowBuilds`); pnpm fails the install on a new unapproved one. Approve or deny it with `pnpm approve-builds <pkg>` / `'!<pkg>'`. `.npmrc` has `engine-strict=true`. `README.md`, `run-windows.cmd` and Playwright's `webServer` command still use `npm` (`npm i --legacy-peer-deps`, `npm run build-integration && npm run preview`). Use pnpm.
- Node: CI uses 24. Generating the client needs Node ≥ 22.18 (`@hey-api/openapi-ts`); building doesn't. There is no `engines` field or `.nvmrc`.
- `.env` (from `.env.raw`): `PUBLIC_API_URL`, `PUBLIC_API_REQUEST_TIMEOUT_MS`, `PUBLIC_COOKIES_EXPIRATION_SPAN_SECONDS`. These are read via `$env/static/public`, so they must exist at build time.
- **Regenerate the API client after any backend route or schema change**, and commit it: `pnpm run generate-client` (needs the backend running at `PUBLIC_API_URL`). CI regenerates it against the PR's backend and fails if the committed client differs.
  - The backend must publish OpenAPI **3.1** (FastAPI's default). On a 3.0 spec, hey-api turns `str | None` fields into `z.unknown()`.
- Dev: `pnpm run dev`. Build: `pnpm run build`. Preview: `pnpm run preview` (port 5174).
- Typecheck: `pnpm run check` (`svelte-kit sync && svelte-check`).
- Lint: `pnpm run lint` (prettier check + eslint). Format: `pnpm run format`.
  - ESLint currently reports warnings only (unused vars, `any`); they don't fail the run. `no-undef` is off for `.ts`/`.svelte` (TypeScript covers it).
- Unit tests: `pnpm run test:unit` (vitest, which runs in watch mode outside CI; use `pnpm exec vitest run` for a single run).
  - `vitest.config.ts` takes precedence over the `test` block in `vite.config.ts`. They disagree on `include`. The effective pattern is `src/**/*.(test).{js,ts}` with jsdom and `vitest-setup.ts`.
- E2E: `pnpm run test:integration` (Playwright; Chromium, Firefox and WebKit projects; CI runs Chromium only).
  - Its `webServer` builds with `--mode integration` (reads `.env.integration`) and previews on 5174.
  - It needs a running backend pointing at a throwaway DB. `README.md` says port 8090; CI uses 8080 via env vars.
  - `pnpm run test` runs integration and then unit.
- Deploy: Vercel via the deploy workflows. The build runs on Vercel with `installCommand` (`pnpm install --frozen-lockfile`) and `buildCommand` (`pnpm run build`) from `vercel.json`; the dashboard has no overrides. The build uses the committed client and doesn't contact the backend. `svelte.config.js` uses `adapter-auto`; `adapter-node` and `adapter-vercel` are installed but not referenced in config.

## Conventions observed in the code

- **Svelte 5 runes only**: `$props()`, `$state`, `$derived`, `$effect`, snippets and `{@render}`. No `export let`, `<slot>`, `createEventDispatcher`, or `svelte/store` usage remains. Component events are callback props (`onSubmitSucceeded`, ...). SvelteKit 2, Vite 5, TypeScript strict.
- Components use `<script lang="ts" module>` for imports and the exported `Props` type, then `<script lang="ts">` with `const { ... }: Props = $props();`.
- Stores: a class with private `$state` fields and a `value$` getter (e.g. `Projects` in `stores/projects/projects.svelte.ts`). Provided via `setProjects(new Projects(...))` and read via `getProjects()`, which may return `undefined`.
- Validation: per-route Zod schemas in `validator.ts`, type-checked against the generated models with `({}) as z.infer<typeof schema> satisfies ProjectCreate;`. Build validators on the generated Zod schemas (`X.extend({...})`, `X.shape.field`) so field limits come from the backend; only override what the form needs (number coercion, `''` → `'-'` descriptions, dates, cross-field `refine`). The backend is the source of truth for limits; never restate them by hand. Edit forms that require a field the update schema makes optional use `requiredField(X.shape.field)` (`$lib/utils/zod`). Form inputs arrive as strings: use `z.coerce.number()`/`z.coerce.boolean()`, and map `''` to `null` before coercing optional numbers (`z.coerce.number()` turns `''` into `0`). Generated Zod schemas are also passed as `errorSchema` to map backend 422s onto form fields.
- Dates: calendar dates such as `due_date` are `YYYY-MM-DD` strings end to end (the backend stores a `date`). Convert with `toIsoDate`/`fromIsoDate` from `$lib/utils/date`, never `new Date('YYYY-MM-DD')`, which reads the value as UTC midnight and shows the previous day west of UTC.
- Files: components are PascalCase `.svelte`. Everything else is kebab-case `.ts`. Each folder has an `index.ts` barrel. Rune-using modules are `*.svelte.ts`.
- Styling: Tailwind 3 + daisyUI 4 (`light`/`dark` themes, dark mode via `[data-theme="dark"]`) + `@tailwindcss/typography`. Classes are passed in as props such as `wrapperClasses` and `inputClasses`. Dynamically built class names must be added to `safelist` in `tailwind.config.js`. Icons come from Font Awesome via `svelte-fa`.
- Formatting (`.prettierrc`): tabs, single quotes, no trailing commas, width 100, `prettier-plugin-svelte`, `prettier-plugin-tailwindcss`.
- Testing:
  - Unit tests are colocated as `Component.svelte.test.ts`, using `@testing-library/svelte/svelte5` and `@testing-library/jest-dom`, selecting by `data-testid`.
  - E2E tests are `*.spec.ts` under `tests/routes/`. They use fixture classes (`Auth`, project or todo helpers) that sign up a random user per test and select by `data-testid` (`PLAYWRIGHT_TEST_ID_ATTRIBUTE`) and roles.
- Inconsistencies (don't copy them):
  - Both `$components/...` and `$lib/components/...` imports are used for the same folder, sometimes in one file (`routes/+layout.svelte`).
  - Validator files are named `validators.ts` under `(entry)/` but `validator.ts` elsewhere.
  - `app.d.ts` references `SHARED_KEYS` without importing it.
